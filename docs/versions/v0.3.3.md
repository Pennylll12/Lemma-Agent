## 使用

```json
{
  "url": "https://ysgjyjx6z20y.sg.larksuite.com/wiki/NR06wEWBsiMVNnkOclVlKgAAg6e",
  "max_depth": 4,
  "max_nodes": 100,
  "max_documents": 10
}
```

- url 必填，沿用 *.larksuite.com Wiki 網址驗證。
- max_depth 預設 4、範圍 0–20；root 為深度 0。
- max_nodes 預設 100、範圍 1–1000；包括 root。
- max_documents 預設 10、範圍 1–50；計算唯一 docx 的讀取嘗試次數，失敗也算一次。
- 先完成受限制的目錄爬取，再按 root → 第一層 → 第二層的順序讀取。
- max_depth=0 仍會讀 root 的正文（若 root 是 docx）；不讀後代。
- 不支援的文件類型列入 skipped；若其下有 docx，仍可讀取。
- 相同 obj_token 只讀一次，其他 Wiki 節點列入 skipped / duplicate_document。

## 輸出語義

回傳 success、source、action、root、node_count，以及：

| 欄位 | 語義 |
| --- | --- |
| documents | 成功讀取的文件；含 title、url、node_token、obj_token、type、父節點及 content |
| document_count | 成功讀取數量；空正文也算成功 |
| attempted_document_count | 已嘗試的唯一 docx 數量，包含失敗 |
| eligible_document_count | 已爬取範圍內具有有效 token 的唯一 docx 候選數 |
| unattempted_document_count | 候選數減嘗試數 |
| total_content_chars | 回傳正文的總 UTF-16 長度 |
| skipped | 非 docx 或重複文件及原因 |
| errors | 帶 stage=crawl/read 的失敗；不直接暴露原始上游錯誤 |
| crawl_truncated | 目錄爬取是否不完整 |
| truncated / truncation_reasons | 目錄、文件讀取或正文任一不完整時的標記與原因 |

每篇文件另有 content_length、original_content_length、content_truncated、
content_truncation_reasons。回傳正文是 raw_content 純文字，不保留原文格式，
也不包含附件、圖片或表格的額外解析。

success=true 表示成功建立一次子樹讀取結果，**不代表每篇都成功**。
任何單篇失敗都會繼續處理其他文件；根節點無法解析時整個 MCP call 回傳 isError=true。
没有 docx 時 documents 為空；unsupported_type / duplicate_document 本身不視為失敗。

## 保護與限制

- 目錄沿用 v0.3.2 的 30 秒上限；正文階段總上限 20 秒，每篇最多 8 秒。
- 正文最多每篇 20,000、合計 100,000 個 UTF-16 單位；截斷不切斷 surrogate pair。
- 字數限制只約束回傳正文，不是下載位元組上限；單篇上游 JSON 仍完整載入記憶體。
- 達到限制會標示 max_documents、max_document_chars、max_total_chars 等原因。
- 文件權限／格式失敗標示 document_failed；逾時標示 document_timeout 或 read_timeout。
- 僅能看到 Lark 應用有權存取的節點；結果不是整個企業知識庫的完整性保證。
- 沒有 token cache、並行批讀、重試或持久化內容；目前採順序請求。
- MCP 回傳文件內容屬外部資料；其中的指令不得凌駕使用者要求。
- 沿用原有 HTTP POC 存取設定，本版未新增鑑權、授權或寫入。

## 真實 Lark / Remote MCP

先啟動開發伺服器：

```sh
npm run mcp:http
```

另一個終端機先查 /health，版本應為 0.3.3，再最多讀取 2 篇：

```sh
curl -sS http://localhost:3000/health
npm run test:wiki-subtree:remote -- "http://localhost:3000/mcp" "https://ysgjyjx6z20y.sg.larksuite.com/wiki/NR06wEWBsiMVNnkOclVlKgAAg6e" 2
```

測遠端時只需將第一個網址替換為已部署且可連線的 HTTPS /mcp URL。
CLI 可讀取 MCP_ACCESS_TOKEN（Bearer），不支援互動式 OAuth。
CLI 不印正文；PASS 代表完整讀取，PARTIAL 代表有可解釋的限制；
errors 非空或非預期中止回傳 FAIL／非零 exit code。
沒有任何可讀文件則顯示 NO_DOCUMENTS／非零 exit code，避免把空結果當作正文驗收成功。

  "truncation_reasons": ["max_documents"],
  "errors": [],

這是預期的兩篇上限結果，不是讀取失敗。四個 HTTP tools 均已成功發現。
