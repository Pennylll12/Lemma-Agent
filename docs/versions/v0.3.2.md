## 輸入與輸出

```json
{
  "url": "https://ysgjyjx6z20y.sg.larksuite.com/wiki/NR06wEWBsiMVNnkOclVlKgAAg6e",
  "max_depth": 4,
  "max_nodes": 100
}
```

- url 必填；接受 HTTPS 的 *.larksuite.com Wiki 網址，可含分享 query / fragment。
- max_depth 預設 4，允許 0–20；root 深度為 0。
- max_nodes 預設 100，允許 1–1000；**包含 root**。
- root 是根節點 metadata；tree 是根節點的子節點陣列，每個子節點都有 children。
- node_count 等於 1 加上 tree 中的唯一節點數。
- truncated 為 true 時不能把結果稱為完整知識庫。
- truncation_reasons 可能是 max_depth、max_nodes、cycle_or_duplicate、
  invalid_pagination、list_failed、timeout、max_pages。
- errors 回報失敗節點；不直接暴露上游錯誤內容。
- success: true 表示 root 已解析並產生結果；仍須檢查 truncated 和 errors。
- 根節點無法取得時，MCP 回傳 isError: true。

URL 只用來提取 token 與組合來源連結；API 請求仍送往既有固定 Lark API host。

## 本地測試

在此專案根目錄執行：

```sh
npm ci --ignore-scripts
npm run test:wiki-tree
npm run test:wiki-tree:mcp
npm test
```

預期：15 tests / 15 pass / 0 fail。測試不需要真實 App ID 或 Secret。
HTTP 測試需要能監聽 localhost；若環境出現 listen EPERM，需允許本機網路測試。
已覆蓋分頁、多層目錄、根節點計數、深度／數量限制、循環／重複、
缺失／重複分頁 token、無限空分頁上限、單分支失敗、輸入驗證與根節點失敗。
MCP 測試驗證 tool discovery、實際 tools/call、既有 read / children 工具、
多次呼叫保持相同 session，以及 DELETE 後舊 session 回傳 404。

## 真實 Lark 與 Remote MCP 驗收

1. 在目標開發環境安裝本版程式與依賴。
2. 透過環境變數或既有本地 .env 設定 LARK_APP_ID、LARK_APP_SECRET。
   不要將 Secret 放進聊天、Git、測試輸出或命令列參數。
3. 執行 `npm run mcp:http`，確認 /health 的 version 是 0.3.2。
4. 在另一個終端執行：

```sh
npm run test:wiki-tree:remote -- "http://127.0.0.1:3000/mcp" "https://ysgjyjx6z20y.sg.larksuite.com/wiki/NR06wEWBsiMVNnkOclVlKgAAg6e"
```

驗證遠端時，將第一個網址替換為**目前實際部署的 HTTPS /mcp endpoint**。
若 endpoint 使用 Bearer token，client 會讀取 MCP_ACCESS_TOKEN 環境變數；
本版本沒有新增伺服器鑑權，也沒有實作互動式 OAuth 登入。

預期輸出包含三個 HTTP tools、session_reused: true、node_count 介於 1 與 100。
完整結果顯示 PASS；受深度／數量限制顯示 PARTIAL；API／結構錯誤會以非零狀態退出。
實際節點數及標題以當時 Lark 回應為準。文件曾記錄根節點「叻媽知識庫」
及「驗樓」「冷氣機服務」；這些是待確認的歷史參考，不是本次實測結果。
此 client 不讀正文；既有 read 工具的實際正文驗收可另用既有 test client。

## 已知限制

- 本次完成 v0.3.2；正文批讀、搜尋、知識清理、Google Drive / CRM 仍屬後續階段。
- 只支援 Lark *.larksuite.com Wiki；不支援 Feishu / 自訂網域。
- 30 秒總逾時、2000 頁總上限；大型目錄可能回傳部分結果。
- 順序請求、沒有重試或 token cache；沿用現有 tenant token 權限模型。
- 到达深度或數量上限時，若 has_child=true 即保守標示截斷，不額外讀取來證明目錄是否為空。
- 無法辨別「應用不可見的節點」與「不存在的節點」；tree 只代表該應用可見範圍。
- 每次爬取不是交易快照，期間 Wiki 有變更時可能出現重複／遺漏。
- 既有 HTTP 仍是 POC：未新增鑑權、授權、rate limit、稽核或 session TTL；
  不能直接當作公司級正式環境部署。
- 既有 auth / 其他工具的錯誤紀錄行為保留；新 crawl 的對外錯誤已去除原始上游內容。
